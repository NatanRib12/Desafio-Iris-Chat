O que você vai mexer

O IRIS é a nossa plataforma de monitoramento de ativos industriais. Ela recebe dados de sensores instalados em máquinas de fábrica, como prensas, misturadores e injetoras, e responde perguntas sobre eles: o que está fora do normal, desde quando, o que provavelmente causou.

O IRIS Chat é uma versão pequena disso, montada só para este exercício. Tem três partes na tela: um menu lateral com as conversas e os ativos, um chat com o agente no meio e um painel com os dados do ativo à direita.

O que tem no repositório
  • Um front em React com Vite e TypeScript, com seis componentes.
  • Uma API em Express, com as rotas de conversas, mensagens e ativos.
  • Dados de exemplo: cinco conversas, mensagens do agente e oito ativos de uma fábrica real nossa, em Montes Claros.
  • Um README.md com o detalhe operacional: como rodar, o que cada arquivo faz e a lista do que as pessoas reclamaram.
Leia isto antes de começar

O app funciona e está cheio de problema. Ele trava depois de alguns segundos, faz muito mais requisição do que precisa, uma parte da tela nunca carrega e a API cai sozinha. Nada disso é acidente: os problemas foram colocados de propósito, e alguns estão escondidos atrás de outros. Não é um exercício de escrever código do zero. É um exercício de enxergar.

Não existe uma lista secreta que você precisa acertar inteira. Existe um app quebrado e você com o navegador aberto. O que interessa é o caminho que você faz entre os dois.

Dois comandos e pronto

Você precisa de Node 20 ou mais novo instalado. Nada além disso. 

$ npm install
$ npm run dev

Isso sobe as duas coisas juntas: a API em localhost:3001 e a interface em localhost:5173. Abra a interface no navegador.

Você não precisa de chave de API de nada

Nem OpenAI, nem Google, nem token nosso. Não tem banco de dados para instalar, não tem Docker, não tem conta para criar, não tem arquivo .env para preencher. Tudo roda na sua máquina, offline.

As respostas do agente no chat são geradas pelo próprio servidor, montando frases com os dados dos sensores que já estão no repositório. Não tem modelo de linguagem por trás, e isso é de propósito: aqui o assunto é o app. A parte de IA vem na parte 2.

O que esperar quando abrir
  • A tela carrega e você consegue usar: clicar nas conversas, mandar mensagem, trocar de ativo.
  • Depois de alguns segundos a página vai ficar pesada. Isso é esperado, é um dos problemas.
  • Em algum momento a API vai cair e o chat vai parar de responder. Também é esperado. Ctrl+C no terminal e npm run dev de novo.
  • Se quiser voltar os dados ao estado inicial, apague o arquivo server/dados.json. Ele é recriado sozinho.

Deixe o DevTools do navegador aberto o tempo todo (F12), na aba Network. Boa parte do que está errado aparece ali antes de aparecer na tela.

Três movimentos

01

Investigar

Use o app como um usuário usaria e observe. Quantas requisições a tela faz? Para onde? Com que frequência? O que o Console mostra em vermelho? O que o terminal da API imprime?

Só depois disso vá para o código. Quem começa lendo arquivo por arquivo demora mais e acha menos do que quem começa olhando o app funcionar errado.

02

Anotar num RELATORIO.md

Para cada problema: onde está (arquivo e linha), o que acontece e por quê, que é o mecanismo e não o sintoma, como você descobriu e como consertar.

Esse arquivo não é burocracia. É o que a gente vai abrir junto depois, para você me contar o que encontrou. Oito problemas bem explicados rendem uma conversa muito melhor que vinte e cinco listados sem explicação.

03

Consertar

Corrija o que você achou, com um commit por problema e a mensagem dizendo qual era a causa. Depois de cada correção, volte no navegador e confirme que resolveu de verdade. Algumas coisas parecem resolvidas e não estão.

Se não conseguir consertar algum, escreva o que tentou e onde travou. Isso é informação útil, não confissão de fracasso.

Como sair do buraco

Você vai travar em alguma coisa. Todo mundo trava. O que separa um dia produtivo de um dia perdido é o que você faz nos vinte minutos seguintes.

Quando não achar a causa
  • Volte um passo e pergunte o que exatamente você observou, sem interpretar. "A tela travou" é interpretação. "A aba Network mostra 400 requisições para a mesma URL em 10 segundos" é observação.
  • Tente fazer o problema acontecer de propósito. Se você consegue reproduzir quando quer, já está com meio caminho andado.
  • Tente fazer o problema parar de acontecer comentando o mínimo possível de código. O que você comentou aponta para a causa.
  • Se depois de meia hora não saiu do lugar, me chama. Travar faz parte, ficar travado calado não.
Como saber se o conserto funcionou
  • Refaça exatamente os passos que reproduziam o problema e olhe o mesmo lugar onde ele aparecia, seja a aba Network, o Console ou o terminal.
  • Cuidado com o conserto que só esconde: se a requisição sumiu da tela mas continua saindo, não está resolvido.
  • Confira se você não quebrou outra coisa. Clique nas outras conversas, troque de ativo, mande mensagem de novo.
Duas coisas que valem para o exercício inteiro
  • Não reescreva o projeto e não troque de biblioteca. Consertar código dos outros é a parte difícil, e é justamente ela que estamos treinando.
  • Pode pesquisar, ler documentação e usar IA à vontade. Só não me traga uma resposta que você não consegue explicar, porque ela não te ajuda em nada no dia seguinte.

Por que este exercício existe

Boa parte do trabalho de quem escreve software não é escrever software. É pegar uma tela travada, sem ninguém dizer por onde começar, chegar na causa e explicar isso para alguém que não leu o código.

Sistema em produção quebra de formas que ninguém previu, e quase nunca vem com a resposta escrita do lado. Este app aqui é um laboratório: os problemas são de verdade, os mesmos que a gente encontra no IRIS, só que concentrados e sem cliente esperando.

Você não precisa achar tudo. Ninguém acha tudo, nem eu.

Quando terminar

Me manda o repositório com os seus commits e o RELATORIO.md na raiz. A gente marca uma hora para você me mostrar o que encontrou.

Dúvida sobre o enunciado, pergunta na hora. Dúvida sobre onde está o problema, tenta mais um pouco antes de perguntar, mas pergunta.
